# Deployment Guide

**Target stack:** React frontend on **Vercel** · FastAPI backend on **Render** · database on **MongoDB Atlas** (all free tiers).

```
Browser ──▶ Vercel (static React bundle)
              │  fetch https://<render-service>.onrender.com/api/...
              ▼
           Render (uvicorn, long-running FastAPI)
              │  MONGODB_URI
              ▼
           MongoDB Atlas (M0 free cluster)
```

Why split: Vercel's serverless Python functions cap at 250 MB uncompressed — the
pandas/numpy stack exceeds it — so the backend runs as a normal service on
Render while Vercel serves only the frontend.

---

## Part 0 — Push the repository to GitHub

Render and Vercel both deploy from a Git host. From the project root:

```bash
git init
git add .
git commit -m "MPLADS AI Sentinel — Render + Vercel + Atlas deployment"
git branch -M main
git remote add origin https://github.com/<you>/jannidhi-portal.git
git push -u origin main
```

`.gitignore` already excludes `.env`, `node_modules/`, build output, and the
live-feed cache — no secrets get committed. `api/` and
`pythonanywhere_wsgi.py` are legacy entrypoints for other platforms; they are
inert in this setup.

## Part A — MongoDB Atlas (database)

1. Sign up / log in at <https://cloud.mongodb.com>.
2. **Build a Cluster**: provider AWS, region closest to your users (e.g.
   `ap-south-1 (Mumbai)` for India), plan **M0 Free**. Creation takes 1–3 min.
3. **Database Access → Add New Database User**:
   - Authentication: Password
   - Username: `jannidhi_app` (any name), password: generate & save it
   - Role: **Read and write to any database** (built-in role)
4. **Network Access → Add IP Address → ALLOW ACCESS FROM ANYWHERE**
   (`0.0.0.0/0`). Render's free tier uses shared/dynamic outbound IPs, so you
   cannot pin them; Atlas + strong DB password is the accepted pattern.
   (On a Render **paid** plan you can restrict to Render's static outbound IPs.)
5. **Connect → Drivers → Python**: copy the SRV connection string:
   ```
   mongodb+srv://jannidhi_app:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
   Keep it — Render needs it in Part B. (`dnspython` for `+srv` is already in
   requirements.txt.)

## Part B — Render (backend)

### Recommended: Render Blueprint (uses the checked-in `render.yaml`)

1. In the Render dashboard: **New → Blueprint**, pick the repository.
   Render reads `render.yaml` and pre-creates the `jannidhi-backend` web
   service (free plan, health check on `/api/health`).
2. Fill the prompted values:
   | Prompt | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas SRV string from Part A |
   | `ADMIN_PASSWORD` | your chosen admin login password |
   | `CORS_ORIGINS` | your Vercel URL — if the frontend isn't deployed yet, enter `https://placeholder.vercel.app` and update it in Part D |
   - `AUTH_SECRET` and `CRON_SECRET` are auto-generated by Render.
3. **Apply**. Build (`pip install -r requirements.txt`) takes a few minutes.
4. When live, note the service URL: `https://jannidhi-backend.onrender.com`
   (name varies if you renamed the service).

### Manual alternative (same result, no blueprint)

**New → Web Service**, pick the repo, then:

- Runtime: **Python** · Plan: **Free**
- Build Command: `pip install -r requirements.txt`
- Start Command: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`
  (single process only — the daily scheduler and sync lock are per-process)
- Health Check Path: `/api/health`
- Environment variables:

| Variable | Value |
|---|---|
| `MONGODB_URI` | Atlas SRV string |
| `MONGO_DB_NAME` | `mplads_sentinel` |
| `AUTH_SECRET` | random 32+ chars (`python -c "import secrets;print(secrets.token_urlsafe(32))"`) |
| `ADMIN_USERNAME` | `Netai` (default) |
| `ADMIN_PASSWORD` | your admin password |
| `CRON_SECRET` | random 32+ chars |
| `CORS_ORIGINS` | your Vercel URL (Part D) |
| `SEED_FROM_SAMPLE` | `1` |
| `MPLADS_LIVE_HOUSE` | `rajya_sabha` (fast). Use `both` to include the ~90 MB Lok Sabha pull — heavy on 512 MB free RAM |

On first boot the lifespan seeds the bundled sample CSV into Atlas (seconds),
creates indexes, and starts the daily live sync at **19:00 IST**.

Verify: open `https://<your-render-url>/api/health` →
`{"status":"ok","database":"connected",...}` (Swagger docs at `/docs`).

## Part C — Vercel (frontend)

1. At <https://vercel.com>: **Add New… → Project**, import the repository.
2. **Root Directory: `frontend`** (critical — otherwise Vercel tries to deploy
   the backend `api/` folder as serverless functions).
3. Settings (auto-detected from `frontend/vercel.json` + Vite):
   - Framework Preset: `Vite`
   - Build Command: `npm run build`
   - Output Directory: `dist`
4. **Environment Variables** (must exist at build time — Vite inlines them):
   | Name | Value |
   |---|---|
   | `VITE_API_URL` | `https://<your-render-service>.onrender.com` |
5. **Deploy**. You get `https://<your-project>.vercel.app`.

`frontend/vercel.json` already contains the SPA rewrite so deep links and page
refreshes work.

---

## Part D — Connect the two (CORS)

1. Copy the Vercel URL (e.g. `https://jannidhi-portal.vercel.app`).
2. Render dashboard → `jannidhi-backend` → **Environment** → edit
   `CORS_ORIGINS` to exactly that URL (no trailing slash; multiple origins
   comma-separated).
3. Save (Render redeploys automatically). If you entered a placeholder in
   Part B, this step is mandatory — the dashboard will show connection
   errors until CORS matches.
4. Custom domain later? Add it to `CORS_ORIGINS` **and** set
   `VITE_API_URL`/redeploy on Vercel accordingly.

---

## Part E — Verify the full stack

1. `https://<render>/api/health` → `status: ok`.
2. Open the Vercel URL — the dashboard renders with seeded sample data.
3. Role selector → **MoSPI Reviewer** → log in with `ADMIN_USERNAME` /
   `ADMIN_PASSWORD`. The header now carries a signed Bearer token.
4. Open any work's case packet and submit a review (proves POST + RBAC +
   Atlas writes all work end to end).
5. Optional: as MoSPI Reviewer press **Sync** — a live portal sync runs in
   the background and the sync banner updates when it lands.

## Part F — Free-tier ops notes

| Concern | What to do |
|---|---|
| **Render sleeps after 15 min idle** (cold start 30–60 s, scheduler paused) | Add a free uptime pinger ([cron-job.org](https://cron-job.org) / [UptimeRobot](https://uptimerobot.com)) hitting `https://<render>/api/health` **every 10 minutes**. This also keeps the 19:00 IST APScheduler sync alive. |
| **Daily sync as an external cron instead** | Alternative/backup: point cron-job.org at `GET https://<render>/api/cron/sync?mode=auto` with header `Authorization: Bearer <CRON_SECRET>` (value in Render → Environment). Runs inline; `rajya_sabha` takes a few minutes. |
| **Data staleness banner** | If syncs lapse >24 h the UI shows a staleness warning — expected when the free service sleeps without a pinger. |
| **Atlas M0 = 512 MB** | The `both`-houses dataset fits but is snug; `rajya_sabha` is comfortable. |
| **Login tokens** | 7-day expiry; signed with `AUTH_SECRET`. Rotating it logs everyone out. |
| **Admin password** | Set via `ADMIN_PASSWORD` on first boot. After the user exists, changing the env var does **not** reset it — update via `mongosh` or wipe the `users` collection and let it reseed. |

### Troubleshooting

- **Frontend shows "Server connection failed"** → `VITE_API_URL` missing/wrong
  at build time (redeploy Vercel), or Render service asleep.
- **Browser console CORS errors** → `CORS_ORIGINS` on Render doesn't exactly
  match the Vercel origin (scheme + host, no trailing slash).
- **Render health check fails** → check logs; usually a bad `MONGODB_URI`
  password or Atlas network access not set to `0.0.0.0/0`.
- **403 on review/sync actions** → not logged in, or token expired
  (re-login).

## Legacy platforms (kept for reference)

- **Vercel full-stack monorepo** (frontend + Python serverless `api/index.py`):
  no longer recommended — the scientific stack exceeds Vercel's 250 MB
  function limit. The old root `vercel.json` for it was:

  ```json
  {
    "builds": [
      { "src": "frontend/package.json", "use": "@vercel/static-build", "config": { "distDir": "dist" } },
      { "src": "api/index.py", "use": "@vercel/python", "config": { "includeFiles": ["backend/**", "model/**", "data/**"] } }
    ],
    "routes": [
      { "src": "/api/(.*)", "dest": "/api/index.py" },
      { "handle": "filesystem" },
      { "src": "/(.*)", "dest": "/frontend/$1" },
      { "handle": "filesystem" },
      { "src": "/(.*)", "dest": "/frontend/index.html" }
    ],
    "crons": [{ "path": "/api/cron/sync", "schedule": "30 13 * * *" }]
  }
  ```

- **PythonAnywhere** (WSGI host): see `pythonanywhere_wsgi.py` — set the WSGI
  file to it and configure the same environment variables as Render.
- **Hugging Face Spaces / any Docker host**: see `README_HUGGINGFACE.md` and
  the `Dockerfile` (single-container frontend + backend).
